# bsrc-agent 技术方案

> Tsecbench 智能攻防 AI 跑分基准平台 · 托管模式 · 初赛参赛作品

## 1. 方案总览

bsrc-agent 是一个**以成熟 Agent 框架为解题引擎、以自研编排层为质量保障**的全自动渗透测试 Agent。核心判断：通用 LLM 自研循环（裸循环 + 工具调用）在长任务上的「计划-执行-反思」能力密度不如成熟的 Claude Code；但 Claude Code 作为单题引擎存在调度盲区（超时管理、并发槽位、多面任务协作、token 失控）。因此采用**「Claude Code 解题 + 自研调度/知识层」**的分层架构，两者边界清晰、各取所长。

### 全流程自动化逻辑（零人工闭环）

```
题目队列 → [调度] 按优先级取题、启动靶场容器
        → [预侦察] nmap 端口 + nuclei CVE 模板（代码自动执行）
        → [解题] 每题 spawn 1 个主控 Claude Code 进程
             ├─ 单 flag easy/medium 题：主进程直接解
             ├─ 多 flag（≥2）/hard 题：主控用 Task 工具一次性并行派发
             │   8/6/4 个子 agent（入口面/内网横向/提权收尾/独立侦察/CVE 专攻/
             │   云逃逸/凭证攻击/收尾直读），子 agent 独立上下文共享主进程运行时
             │   （run 12231 复盘：24 个独立进程吃爆 8核16G 沙箱，子 agent 架构
             │   资源占用降一个量级）；按缺口迭代再派新一轮
             └─ 提前退出：当场断点重跑一次（复用主控角色）
        → [提交] 三通道闭环：submit_flag.sh 直连平台 + 输出流 flag 捕获兜底
             + STATE.md 登记行扫描（子 agent 内部提交对主进程流不可见时的记账兜底）
        → [早停] flag 全部入账 → 完成事件杀进程组，不占槽位等超时
        → [落库] 解法摘要写入 solutions.json（completed 不降级 + partial 断点标记）
             + stdout SOLNOTE 回传
        → [轮转] 未解出题进 retry 队列（首轮限时快速失败，重试轮给足超时）
```

### 关键技术决策与依据

| 决策 | 依据（线上实测） |
|---|---|
| Claude Code 直解而非裸 LLM 循环 | 裸循环复现失败重探索/多阶段题能力密度不足（历史复盘 587 步白跑）；CC 原生循环 + 长上下文管理成熟 |
| 多 flag 题主控 + Task 子 agent 分治 | 单进程 context 爆炸：b-02 单会话 920 万 token 仍 0 解；独立多进程吃爆沙箱（run 12231 复盘）；主控派发子 agent（独立上下文共享运行时）后 b-01（4 flags）首轮拿全 1200 分 |
| flag 全部入账即早停 | 单主进程架构槽位稀缺：完成事件触发杀进程组，不白占 3 槽位等模型自己收尾/超时 |
| hard 首轮 20min 快速失败 | 40min 白耗历史：a-16 首轮 40min 失败、重试 85min 才解出；快速失败留断点，重试轮更高效 |
| token 熔断按成本加权 | cache 命中重读占 token 97%（价格 1/10），全额计入会误杀正常题（a-07 1.9min 被误杀实测）；加权后正常题放行、失控长线仍受限 |
| flag 双通道 + 格式校验 | submit_flag.sh 直连平台保证提交成功；输出捕获通道兜底漏网 flag；格式校验拒绝 tsec{...} 等模型猜测 |
| 解法库跨轮复用 | 已解题复现速度提升 3 倍（9703 轮 4 分钟 3 题 vs 初轮 1-2 分钟/题现场解） |

## 2. 系统架构

```
┌────────────────────────────── 调度层（scheduler）──────────────────────────────┐
│ 平台协议接入（start/close/submit/hint）· 3 并发槽位 · 409 轮转冷却不降级          │
│ 难度分级超时（easy 8/15 · medium 12/25 · hard 25/35/40min 按尝试次数递增）        │
│ 重试队列（retry_unsolved）· NEVER_STOP 轮转 · 题目优先级排序                    │
├────────────────────────────── 执行层（worker → harness）───────────────────────┤
│ 每题 spawn 1 个主控 Claude Code：-p stream-json 流式解析 · 逐行 flag 捕获回调    │
│ 主控 + Task 子 agent（flag≥2/hard）：8/6/4 方向并行，line_X/ 独立工作目录        │
│   + 共享文件软链（NOTES/STATE/RELAY/submit_flag.sh 进各 line 目录，cwd 漂移防踩）│
│   子 agent 独立上下文共享主进程运行时（对比旧 24 独立进程架构内存降一个量级）      │
│ flag 三通道：submit_flag.sh 直连 + 事件流捕获 drain（20s 周期）+ STATE.md 扫描   │
│ 完成早停：flag 全部入账 → 完成事件杀进程组（stop_event 贯穿 run_harness）        │
│ token 熔断：assistant 步级 usage 累计（cache_read×0.1 成本加权；默认关闭——       │
│   子 agent usage 不进主进程流会低估）；kill 整个进程组防孤儿                     │
│ 快速重跑：claude 正常退出但 flag 未拿全 → 当场断点重跑（半额超时，1 次，复用主控）│
├────────────────────────────── 知识层（跨轮复用）───────────────────────────────┤
│ solutions.json：63 题解法库（53 completed + 10 断点），注入 prompt 直接复现      │
│ notes.json：官方 hint 6 条（含多阶段题攻击面提示）                              │
│ intel.json：跨题情报 2 条（flag 提交容器状态约束、JDWP 平台加固）               │
│ 代码化知识：端口→CVE 库 11 项（8188=ComfyUI、5005=JDWP…）+ 组件 CVE 指纹 18 项   │
├────────────────────────────── 基础设施（Docker）───────────────────────────────┤
│ ClawGod 版 Claude Code（第三方 API 缓存修复/CYBER_RISK 拒绝移除）               │
│ nmap + nuclei（4104 CVE 模板）+ PayloadsAllTheThings + 精简词表                  │
│ 权限白名单 settings.json（root 禁用 skip-permissions）· LLM 网关 URL 改写        │
│ 启动自检：平台连通 + LLM 连通 + Anthropic 通道探测（非 2xx 拒绝启动防 0 分空转） │
└────────────────────────────────────────────────────────────────────────────────┘
```
