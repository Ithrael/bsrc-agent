# bsrc-agent 技术方案

> Tsecbench 智能攻防 AI 跑分基准平台 · 托管模式 · 线下总决赛参赛作品

## 1. 方案总览

bsrc-agent 是**以成熟 Agent 框架为解题引擎、自研调度/纪律层为质量与效率保障**的全自动渗透测试 Agent。核心判断：Claude Code 的原生「计划-执行-反思」循环在单题攻坚上强于自研裸循环，但存在长任务调度盲区（并发槽位、止损、提交质量、token 失控）；因此采用「Claude Code 解题 + 自研编排」分层架构，各取所长。

### 全流程自动化逻辑（零人工闭环）

```
题目队列 → [调度] 优先级取题、启动靶场（有断点/剩一面优先）
        → [预侦察] nmap 端口 + nuclei CVE 模板 + HTTP 指纹（代码自动执行）
        → [解题] 每题 1 个主控 Claude Code（flash 快扫 / pro 攻坚分层）
             ├─ easy 单 flag：主进程直接解（首轮不开深度思考，吞吐优先）
             ├─ 多 flag/hard：Task 工具并行派发 8/6/4 个子 agent
             │   （入口/横向/提权/侦察/CVE/云逃逸/凭证/收尾直读），
             │   line_X/ 独立目录 + 共享文件软链（RELAY/HOSTS/NOTES/STATE）
             └─ 完成即取消兄弟线；提前退出当场断点重跑一次
        → [提交] 三通道闭环：submit_flag.sh 直连（CLAIM/EVIDENCE 证据闸门）
             + 输出流捕获（错提≥10 次自动熔断）+ STATE.md 登记扫描
        → [指挥] retry 轮：官方 hint 置顶注入 + advisor 定向 brief + critic 审查
        → [轮转] 预算分级（有断点满额/无断点 12min 快验）；
             attempt≥2 零进展 → 退出常规轮转（末尾回查轮仍回挖）
        → [收尾] 最后 45 分钟 endgame：只放行快赢题，不开新硬题
```

### 关键技术决策与依据（线上实测复盘）

| 决策 | 依据 |
|---|---|
| Task 子代理分治而非多进程 | 独立进程架构实测 24 个 claude 吃爆 8核16G 沙箱、后半程秒退空转；子代理共享运行时后资源降一个量级 |
| RELAY 接力块 + HOSTS 资产台账 | 会话超时被杀时笔记来不及写=断点全丢；强制「达成原语即落盘」+ 机器可读主机/凭据/flag 台账，跨线跨轮共享 |
| CLAIM/EVIDENCE 提交纪律 | 对标榜首梯队 69 flag 仅 4 错提：提交必须声明 RAW EVIDENCE 来源，推断/猜测禁止提交 |
| 全通道错提熔断 | 一轮 145 次错提全部绕过脚本闸门走输出捕获通道；熔断下沉 FlagSubmitter 后所有通道统一生效 |
| hint 经济学 | hint 每条扣该题 10% 但解不出的题上扣 0——hard/多 flag 首轮即买方向，买一次落盘终身免费复用（重复购买纯烧分） |
| 预算分级 + 零进展退出 | 同题三轮满预算重攻零产出实测烧掉 213 分钟；有断点保持满额（短预算曾丢 860 分），无断点降 12min 快验，两轮仍零进展则让出槽位 |
| endgame 收尾策略 | 收卷前 25 分钟还在第三轮攻零进展题的实测教训：尾段只打剩一面/可复现题 |
| effort 分级 | 探测超时曾致全轮无深度思考（pro 只出知识不出思考）；medium/hard 全程满思考、easy 次轮再上——深度与吞吐兼得 |

## 2. 系统架构

```
┌────────────────────────── 调度层（scheduler）──────────────────────────┐
│ 3 并发槽位 · 优先级（复现>剩一面>单flag新题>多flag）· 409 轮转冷却       │
│ 预算分级（easy 8/15 · medium 12/25 · hard 25/35/40；无断点降 8/10/12）  │
│ 零进展退出（attempt≥2 无 flag 无断点不入 retry，末尾回查轮回挖）        │
│ endgame（开跑满 300min 后只放行快赢题）· 容器轮换检测与元数据注入        │
├────────────────────────── 执行层（worker→harness）─────────────────────┤
│ 主控 Claude Code + Task 子代理（8/6/4 方向）· 完成早停止损               │
│ 共享状态：RELAY.md（原语/死路/下一步）· HOSTS.md（资产台账）· STATE.md   │
│ flag 三通道提交 · drain 20s 周期 · 进程组回收（killpg 三次补刀防孤儿）   │
├────────────────────────── 纪律与策略层 ─────────────────────────────────┤
│ submit_flag.sh 证据闸门（EVID<6 字符拒绝）+ 连错干预 + 来源闸门          │
│ FlagSubmitter 全通道熔断（auto 通道累计错提≥WRONG_SUBMIT_CAP 关闭）      │
│ advisor brief（强模型读全部进度产出定向指令）+ critic 对抗审查           │
│ hint 置顶复用 · effort 分级 · haiku 杂务槽钉死 flash（防网关兜底路由）   │
├────────────────────────── 基础设施（Docker 镜像）───────────────────────┤
│ 横向四件套：fscan（内网一把梭）· chisel（隧道穿透）· flag_sweep（清点）  │
│   · creds_replay（凭据重放）+ proxychains4                              │
│ nuclei（4104 CVE 模板）· PayloadsAllTheThings · 精简词表                │
│ 启动三重自检（平台/LLM/Anthropic 通道 + effort 探测三分支）              │
└─────────────────────────────────────────────────────────────────────────┘
```

## 3. 量化指标表现（Tsecbench v1 · 托管模式 · 6 小时 · 干净镜像）

### 3.1 总分与发现率（run 12464）

| 指标 | 数值 |
|---|---|
| 最终得分 | **19655 / 23000（85.45%）** |
| flag 捕获 | **64 / 74 枚**，56 题全对、2 题部分得分 |
| 能力雷达 | 云攻击 100 · 对抗规避 99.29 · 漏洞利用 92.47 · Web 88.34 · 二进制 82.84 · 多阶段渗透 60.71 |
| 模型分工 | pro 攻坚 76.4%（3.5 亿 token/6956 次）+ flash 快扫 23.6%（2.7 亿/5338 次） |

### 3.2 提交质量与治理

| 指标 | 实测 | 治理手段（决赛版已落地） |
|---|---|---|
| 提交命中率 | 64 正确 / 209 总提交（31%） | CLAIM/EVIDENCE 证据闸门（预期错提 145→<30） |
| 盲猜循环 | 单题最高 75 连错 | 全通道错提熔断（≥10 次关闭 auto 通道） |

### 3.3 人机验证时间比例

**0%**。全链路无人值守；人工仅在轮次间（非评测时间）做复盘与参数迭代。

## 5. 合规与安全声明

- 全部攻击行为仅在 Tsecbench 官方隔离靶场内进行，不涉及任何真实系统；
- **镜像零题目先验**：不含解法库、历史 flag、题目专属打法或任何预置答案——平台「不可内置题目记忆」规则全程遵守，全部成绩为干净镜像现场解出，平台侧会话/流量审计可验证；
- 镜像不含任何密钥（LLM API Key 等经平台动态环境变量注入）；
- 官方 hint 的购买与扣分遵循平台计费规则，同题 hint 落盘复用不重复购买。
